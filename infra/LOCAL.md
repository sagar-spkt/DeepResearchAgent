# Local dependencies

Copy .env.platform.example to an ignored .env.platform, choose a random database password and a 64-character hexadecimal encryption key. Run `docker compose --env-file .env.platform up -d postgres` for application persistence. Containers bind database/console ports to 127.0.0.1 only.

Optional observability: run `python3 scripts/setup_local_langfuse.py --enable-app-tracing`, then `docker compose --env-file .env.platform --profile observability up -d valkey clickhouse seaweedfs seaweedfs-init langfuse langfuse-worker`. This creates a local SeaweedFS S3 bucket and bootstraps a single owner/project/API key with open signup disabled. Generated credentials stay in ignored owner-only `.env.platform`, `.env` and `local-data/langfuse/seaweedfs-s3.json` files. Local startup and synthetic trace ingestion have been verified. Local image tags are explicit versions but not verified immutable digests; resolve supported images and pin digests before any AWS deployment. Docker Desktop's 8 GiB allocation is below the published ClickHouse guidance for production-sized service resources; this local stack is intended for low-load development.

Application processes can run through the parent project's backend/frontend commands with `research-operator` credentials for real Bedrock tests. The full Compose application services are also pinned to Bedrock and real BGE embeddings; they never fall back to fake responses. Compose does not mount host AWS profile credentials, so provide a deliberate container credential source or use the documented host API/worker commands. Fake remains the offline-test provider only. No vLLM GPU container runs on a Mac by default. Docker volumes retain local state; do not use `down -v` unless intentionally discarding it.
