# Python dependency license inventory

This inventory records selected Python model and build dependencies examined while making the Python lock reproducible, including transitive build-tool dependencies. It is not a complete inventory of every transitive Python, Node, container, model, or system-package license. Re-run a reviewed license scanner against the final release SBOM before publishing an image.

## Lockfile metadata audit (2026-11-14)

- `web/package-lock.json` has 229 `node_modules` package records and each record declares a `license` value. There are nine distinct values: `MIT`, `Apache-2.0`, `LGPL-3.0-or-later`, `Apache-2.0 AND LGPL-3.0-or-later`, `Apache-2.0 AND LGPL-3.0-or-later AND MIT`, `ISC`, `BSD-3-Clause`, `CC-BY-4.0`, and `0BSD`. The count includes optional platform-specific packages that are not all shipped in every image. Review the LGPL and CC-BY terms and obligations against the actual Linux release artifact before redistribution; lockfile declarations alone are not legal approval.
- `uv.lock` has 151 package records and declares no license field on any record. The local Python environment contained exact versions for 90 locked distributions; 89 of those exposed a license expression, `License` value, classifier, or license-file field in installed metadata. This does not cover the other locked versions or establish completeness of the license text. The offline Trivy lockfile scan also found the package graph but returned no license fields. A full source/license scan of the installed Torch environment did not complete within this session, so no Python-wide license result is claimed.
- Container base images, OS packages, model weights, vLLM release artifacts, and the final published application images still need a reviewed artifact-level SBOM/license scan. Capture the scanner/version, image digest, platform, complete reports, and resolution of non-permissive or ambiguous terms as release evidence.

## Current local environment metadata audit (2026-11-15)

The current `uv.lock` contains 151 package records representing 150 distinct normalized package names; one package has two platform/source variants. A read-only comparison against `.venv` distribution metadata found 127 exact normalized package-name matches, including the local `deep-research-agent` project, and license expression/classifier or license-file metadata on all 126 matched third-party distributions. The other 23 distinct locked package names were not installed in this environment. Nineteen are CUDA/NVIDIA/Triton packages from the non-CPU PyTorch lock variant; `colorama` and `httpx2-jsfetch` are guarded by Windows and Emscripten markers in `uv.lock`; `greenlet` is present in the retained application SBOMs with `MIT AND PSF-2.0` metadata; and the locked Python `tzdata` variant is Windows-only, while the Linux images contain Debian `tzdata` marked public domain. Exact-release PyPI metadata was checked for three platform-specific packages: Colorama 0.4.6 states BSD 3-Clause, httpx2-jsfetch 1.0 declares BSD-3-Clause, and tzdata 2026.6 declares Apache-2.0 (references below). The retained Linux/amd64 CPU embeddings SBOM (`local-data/security-validation/2026-11-15-runtime-images/embeddings-sbom.cdx.json`) contains `torch` 2.15.0+cpu and no CUDA, NVIDIA, or Triton components. This is artifact-specific evidence for the supported CPU target, not evidence about every platform's resolved environment or the vLLM image. It does not inspect source license texts, model artifacts, or legal obligations. The 2026-11-14 inventory below remains incomplete for those reasons. The owner selected Apache-2.0 and the project now declares it in `LICENSE`, Python package metadata, and web package metadata; the locally built wheel includes `LICENSE` and `License-Expression: Apache-2.0`. The Trivy 0.76.2 source-only scan still omits the first-party SPDX license from its CycloneDX component; the post-license image SBOMs below do include Apache-2.0 for the shipped backend and web components.

The current source tree's Trivy CycloneDX scan is retained at `local-data/security-validation/2026-11-15-runtime-images/source-sbom-apache-2.0.cdx.json` (SHA-256 `55a319fc997569ca60fd47f8ae3cf763842145f63e94cb699b0c5c73e5cd47cc` — see exact local artifact for its full digest). The scan skipped local environments, cached/generated data, Git metadata, and Terraform work directories. It is source-tree evidence, not a rebuilt-image SBOM or a complete distribution/license review.
