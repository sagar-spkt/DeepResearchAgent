# CodeBuild executor network permissions

`infra/expiry/network-permissions.tf` supplies an inline identity policy for the existing expiry executor role. It is Terraform source only: no IAM policy has been attached in AWS. It grants the VPC-network operations needed by CodeBuild without granting runtime deployment, backup, destruction, state access, or Kubernetes permissions.

The policy binds network-interface creation to the supplied exact management subnet and security-group ARNs, plus the new network-interface ARN pattern in the current account and Region. Network-interface IDs are not known before creation. AWS authorizes the create operation against its interface, subnet and applicable security-group resources; subnet/security-group resource scopes control placement. No interface tags are assumed.

Deleting an interface is allowed only in those management subnets and the exact management VPC. The EC2 API rejects deleting attached interfaces. Within that network, the role can delete another detached interface, so use a dedicated session management subnet and treat the executor as a trusted operations identity. The policy does not prove interface ownership by this build. Creating interface permissions additionally requires `ec2:AuthorizedService=codebuild.amazonaws.com`, with the same subnet/VPC conditions. EC2's authorization reference explicitly supports both `ec2:Subnet` and `ec2:Vpc` for these interface operations.

The five EC2 describe actions use `Resource: *` because AWS does not support resource ARNs for those actions. They remain constrained to the configured Region. Mutation statements never use a bare wildcard resource; the interface ARN pattern is account/Region scoped and network placement/deletion is constrained as above. Inputs must contain distinct, nonempty, exact subnet/security-group IDs and distinct management/runtime VPC IDs; this reviewed source supports `us-east-1` only. It does not inspect AWS to prove the supplied resources belong to the expected environment/session. Bind those inputs to reviewed management Terraform outputs and verify live resource scope before apply.

## Integration and validation gates

The CodeBuild project and expiry schedule explicitly depend on `aws_iam_role_policy.executor_network` in `infra/expiry/main.tf`, ensuring the policy is created first. Provision the session management network, reviewed executor role and this policy before launching any build. These Terraform dependencies do not establish live readiness; the schedule must not be enabled until all network, role, artifact and backup prerequisites pass.

`infra/expiry/tests/network-permissions.tftest.hcl` uses a mocked AWS provider and plan-only tests. It verifies account/Region/network scopes and rejects malformed IDs, duplicates, empty security groups and wildcard Region inputs. These are not IAM simulation or live CodeBuild evidence. Before staging acceptance, verify the build can create and remove its interface only in the approved network, can reach the restricted EKS API through the configured NAT address, and cannot create/delete interfaces in other subnets. Effective permissions from other policies, permission boundaries and organization SCPs remain unverified.
