# Remaining work plan

This is the actionable queue for completing local acceptance and preparing the portfolio project for a reviewed AWS release. `docs/implementation-roadmap.md` remains the architecture-level history; this document tracks the concrete next actions, dependencies, gates, and parallel work plan.

## Execution rules

- A task closes only when its acceptance evidence is recorded here or in the linked subsystem doc. Static tests do not count as live-model, browser, AWS, or restore evidence.
- Use independent implementer, reviewer, and validator roles from `agent-config/roles/`. Reviewers do not edit. Validators run checks on the final revision.
- Concurrent writers use separate Git worktrees and bounded tasks; do not have two writers edit the same files. Merge/rebase and rerun affected checks before marking tasks complete.
- GitHub CLI, repository API access, Git metadata writes, and Docker are now available in this session. The current accumulated changes are being reviewed and validated on `feat/local-readiness-and-ci-fixes`; publish only that branch, never merge it automatically.
- Keep local, staging, and production credentials/data isolated. Never check in secrets, private transcripts, uploaded documents, database dumps, Terraform state, or credentials.
- Fake providers are for offline tests only. Real Bedrock, Tavily, GPU, and AWS calls require explicit configuration and authorization, a documented upper bound, and no silent paid fallback.
- AWS staging and production work is serialized under the shared lifecycle lease and four-vCPU G/VT limit. A code change, green CI, or cost estimate does not authorize deployment or spend.
- Shutdown preserves retained data. Full purge is a separate, explicit task after verified backups.
